## 1. Scope & rules met

- A **small, bootstrap-safe local Git Workspace Tool** (`GitWorkspaceTool` static facade) that talks
  **only** to the local `git.exe` and the local filesystem. No distributed/remote/cloud service is
  created or contacted.

  through `ProcessStartInfo.ArgumentList` (never shell-interpolated) — no command-injection surface.

## 2. Safety model

The tool is read-only with respect to branch history and repository content except for the specific
worktree directory it creates/removes.

| Safety property | Mechanism |
|---|---|
| Never runs against a non-repo | `RequireRepository` first checks `git rev-parse --git-dir` exit code. |
| No shell interpolation | `ProcessStartInfo.ArgumentList`; every user-controlled string is a separate argument. |
| No destructive git built-ins | The tool never runs `git branch -D`, `git clean -fd`, `git reset --hard`, `git add`, `git commit`, `git push`, or any `-f` beyond the explicit `worktree remove --force` opt-in. |
| Deterministic, safe paths only | `<repo>\.forge\worktrees\<BranchSlug>`; `BranchSlug` refuses `..`, leading/trailing dot, control chars, and Windows device names, and escapes literal hyphens so slash-vs-hyphen cannot collide silently (see §4). |
| Never overwrites | `CreateWorktree` refuses a non-empty target path and refuses when the path is already a registered worktree. |
| Refusals, not exceptions | Every expected failure returns `WorkspaceResult(Success=false, Message, Detail)`. |
| Timeouts | git runs are bounded (60 s default) and killed on timeout. |

## 3. API surface

Single static facade `GitWorkspaceTool` in namespace `DevBridge.Workspace`, plus small supporting types.

```csharp
public sealed record WorkspaceResult(bool Success, string Message, string? Detail = null)
    { public static WorkspaceResult Ok(...); public static WorkspaceResult Fail(...); }

public sealed record WorktreeRecord(string Path, string? Branch, bool Detached, string? HeadSha);
public sealed record WorktreeStatusInfo(string Branch, string HeadSha, bool IsClean,
                                        int UntrackedCount, string[] DirtyEntries);
public static class BranchSlug { public static string? ToSlug(string? branch); }

public static class GitWorkspaceTool
{
    public static WorkspaceResult CreateWorktree(string repositoryPath, string branch, out string worktreePath);
    public static WorkspaceResult ValidateWorktree(string repositoryPath, string branch);
    public static WorkspaceResult ListWorktrees(string repositoryPath);       // Detail = JSON WorktreeRecord[]
    public static WorkspaceResult GetWorktreeStatus(string repositoryPath, string branch); // Detail = JSON WorktreeStatusInfo
    public static WorkspaceResult RemoveWorktree(string repositoryPath, string branch, bool force = false);
    public static WorkspaceResult PruneWorktrees(string repositoryPath);
}
```

Structured payloads (list/status) are carried as documented JSON in `WorkspaceResult.Detail` so the
facade keeps a single, uniform result type. `out string worktreePath` is `""` on every refusal and the
created path on success (per the locked contract).

### `CreateWorktree` refusals (in order)
1. repository path missing / not a git repository;
2. branch missing / blank;
3. branch is `main` (trunk — `OrdinalIgnoreCase`);
4. branch equals the repository's current `HEAD` branch;
5. a worktree for that branch is already registered (`git worktree list --porcelain`);
6. the branch already exists locally **or** on any remote (`for-each-ref refs/heads` +
   `refs/remotes`);
7. `BranchSlug.ToSlug` returns `null` (unsafe/ambiguous name);
8. deterministic target path already exists and is non-empty (or exists as a file).

Success path: `git -C <repo> worktree add -b <branch> <target>`, then verify
`git -C <target> rev-parse --show-toplevel` equals the target path (Windows path-equality, case
insensitive).

## 4. Deterministic path rule

Every worker branch maps to exactly one directory:

```
<repositoryPath>\.forge\worktrees\<branchSlug>
```

`BranchSlug.ToSlug` is deterministic and Windows-safe:

- allowed literal output chars: ASCII letters/digits, `_`, internal `.` — **lower-cased** so the
  segment is stable on case-insensitive Windows filesystems;
- a literal `-` in the branch is **escaped to `--`** so it is never confused with the separator marker;
- every run of separator characters (`/`, `\`, whitespace, and any Windows-reserved/unsafe char such
  as `< > : " | ? *` and control chars) is collapsed to a single `-`; leading/trailing separator runs
  produce no marker;
- refused (`null`): empty/whitespace, ASCII control chars, any `..`, leading or trailing `.`,
  Windows reserved device names (`CON/PRN/AUX/NUL/COM1-9/LPT1-9`).

Resulting examples exercised by the harness:
`feature/x/y → feature-x-y`, `feature with spaces → feature-with-spaces`,
`Feature/One → feature-one`, `feat:ure<x> → feat-ure-x`, `feature-x → feature--x`
(literal hyphen escapes so it differs from `feature/x → feature-x`).

Because the mapping is deterministic, a repeated request for the same branch always resolves to the
same path; because create-time refuses any path that is already a worktree or non-empty directory, the
tool never constructs two worktrees at one path and never writes over existing content.

## 5. Branch ownership rule (one worker → one branch → one worktree)

- `CreateWorktree` only creates a worktree for a **brand-new** branch (`git worktree add -b`) and only
  when that branch exists neither locally nor on a remote. A worker never "takes over" an existing
  branch.
- The branch/`HEAD`/worktree identity is re-verified by `ValidateWorktree` and `GetWorktreeStatus`
  (registered worktree exists → is a git repo → `symbolic-ref HEAD` equals the requested branch).
- One branch therefore maps to at most one live worktree at a time. `ListWorktrees` exposes the full
  registry so callers can confirm ownership before acting.

## 6. Removal semantics + refusal cases

`RemoveWorktree(repositoryPath, branch, force = false)`:

- Refuses when: repository not a git repo; branch blank; branch is `main`/trunk; branch is the
  repository's current `HEAD` branch (the primary worktree); no worktree is registered for the branch;
  or the worktree is **dirty** and `force` is false.
- Dirty detection is read-only (`git -C <worktree> status --porcelain`). On a refused dirty removal the
  `Detail` field lists every porcelain entry (each names the file), so the caller can see exactly what
  blocks removal.
- Safe path runs `git -C <repo> worktree remove <path>`; `force=true` adds `--force` and is the **only**
  force flag this tool can pass.
- The tool **never deletes the branch** after removing a worktree (verified in the harness:
  `git show-ref refs/heads/<branch>` still exits 0 after removal). Branch cleanup is intentionally out
  of scope.

`PruneWorktrees` runs `git -C <repo> worktree prune` (read-only with respect to content).

## 7. Human-merge-gate preservation

The whole point of a worker lane is that a human merges it. This tool is deliberately unable to
circumvent that gate:

- It never deletes branches, so a completed worker branch survives its worktree and can be reviewed /
  merged by a human on `main` at whatever cadence the process requires.
- It refuses to create worktrees for `main` or any existing branch, so it cannot accidentally place a
  worker on the trunk.
- It refuses to remove the primary/current-branch worktree, so the repository's own checkout is never
  at risk.
- No `push`, no `merge`, no `fetch`, no `reset`, no `clean`, no index mutation — nothing that could
  rewrite history or move the shared remote state.

## 10. Risks & assumptions

- **Slug injectivity is practical, not absolute.** The escaping scheme is injective over the realistic
  universe of valid git refs using `[A-Za-z0-9._-]` plus `/`. Residual collisions are defended at
  create-time by refusing any deterministic target path that already exists or is a registered
  worktree, so an ambiguous path is never constructed. Branch names containing characters that are
  valid in git but unsafe on Windows (e.g. `~`, `^`, `@`) collapse through the separator marker and
  could collide with a slash-shaped name; such a second create is refused by the path guard, never
  silently merged.
- **Case-folding.** Slugs are lower-cased for case-insensitive filesystems. Distinct refs that differ
  only by case will contend for one path; the guard refuses the second, which is the intended safe
  behaviour on Windows.
- **Empty pre-existing target dir** is left to git (confirmed `git worktree add` succeeds into an empty
  dir on git 2.51). Non-empty target dirs are refused before git runs.
- **Bare repositories** are not explicitly handled; the tool assumes a non-bare working clone, which is
  the canonical Forge shape.
- **git executable on PATH** is required; `GitRunner` surfaces a clean failure if git cannot be started.
- **`force=true`** will discard uncommitted/untracked files in that one worktree via `git worktree
  remove --force`; the branch and all other worktrees are untouched. This is the only destructive
  opt-in in the API and is not the default.
- **No network**: remote-branch detection relies only on local remote-tracking refs
  (`refs/remotes/*`). A branch that exists only on the remote and has never been fetched will not be
  detected — `git worktree add -b` would then create a divergent local branch. If this is a concern,
  add an explicit `git ls-remote` heads probe (still local-only, requires network to the origin) as a
  confirm item.

## 11. Decisions a human must confirm

1. **Reserved slug policy** — `BranchSlug` currently refuses Windows device names (`CON`, `NUL`,
   `COM1-9`, `LPT1-9`). Confirm refusal is preferred over a deterministic re-map (e.g. prefixing) for
   a branch literally named `con`.
2. **`main` is hard-refused as the trunk name.** If a Forge repository ever uses a different trunk
   (e.g. `master`, `trunk`), `TrunkBranch` is a one-line constant to revisit; the current-branch guard
   already protects a non-`main` default.
3. **No remote existence probe** — local-only remote-tracking check (§10). Confirm whether an
   explicit `git ls-remote` head probe should be added before `worktree add -b` for safety against
   never-fetched remote branches.
4. **`.forge` directory placement** — worker worktrees live under `<repo>\.forge\worktrees`. Confirm
   `.forge` should be added to the repo `.gitignore` so stray worker worktrees never become tracked.
5. **Removal never deletes the branch** — intentional (human-merge gate). Confirm the external
   workflow that cleans up merged worker branches (e.g. `git branch -d`) lives outside this tool.
