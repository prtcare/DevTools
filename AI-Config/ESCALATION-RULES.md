\# NEXUS ESCALATION RULES



STOP implementation and request a decision when:



1\. Requirements are genuinely ambiguous.

2\. Documentation contradicts itself.

3\. Another active development task conflicts with the change.

4\. Repository ownership is unclear.

5\. A Nexus layer boundary would change.

6\. A major architectural decision is required.

7\. Existing functionality must be removed.

8\. A public contract/API needs breaking changes.

9\. A destructive database operation is required.

10\. Production infrastructure is affected.

11\. Credentials or secrets require modification.

12\. The requested work exceeds the assigned task.



When escalating, report:



\## ISSUE



What was discovered.



\## AFFECTED TASK



Milestone / Feature / Task / Work Item.



\## AFFECTED FILES



Files/repositories involved.



\## OPTIONS



Option A

Option B

Option C if applicable.



\## RECOMMENDATION



Recommended option and reason.



\## STATUS



Work paused awaiting decision.



Do not continue until instructed.
