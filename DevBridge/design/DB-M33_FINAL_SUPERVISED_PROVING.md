# DB-M33 — FINAL SUPERVISED DEVBRIDGE PROVING

- Milestone: DB-M33
- DateUtc: 2026-09-01
- Status: DESIGN RECORD (result recorded in state/db-m33-result.json)

## 1. Objective

Prove that DevBridge can support a **complete supervised development workflow
safely and coherently from task selection through trial safe-stop**:

START NEXT CYCLE -> M03 selects a legitimate implementable task -> dependency
lineage/context resolved -> M04 reservation -> M05 ChatGPT handoff -> HUMAN
HANDOFF (fixture-controlled) -> implementation result registration -> M06
verification -> M07 Claude review package -> HUMAN Claude decision (controlled
proving evidence) -> M08 -> correction path where required ->
TRIAL_CYCLE_SAFE_STOP -> CLOSE_TRIAL_CYCLE. **No M10 in TRIAL mode.**

DB-M33 is a **FINAL SUPERVISED PROVING** milestone. It is NOT an autonomy
development milestone. DevBridge remains TEMPORARY, SUPERVISED scaffolding.

## 2. Proving method (verbatim intent)

- DB-M33 must NOT require uncontrolled real AI/provider execution.
- Human/external boundaries are proven with **controlled artifacts/fixtures**
  representing: ChatGPT output, Claude Code / DeepSeek implementation result,
  Claude review decision.
- The actual DevBridge transitions, validation, state handling and evidence
  generation use the **REAL hardened DevBridge backend/UI paths**.
- **Do NOT fake DevBridge state transitions by directly editing JSON.** The
  only JSON the harness writes is fixture *seed* state (proving-history,
  closure record, overlay evidence, controlled external artifacts). Every
  lifecycle transition (PREFLIGHTED -> RESERVED -> AWAITING_CHATGPT_PROMPT ->
  VERIFIED -> CLAUDE_REVIEW_PASSED_TRIAL -> TRIAL_CYCLE_SAFE_STOP ->
  TRIAL_CYCLE_CLOSED) is produced by the real backend script reading its real
  state and executing its real governed write.
- **TRIAL mode only.** The environment is NOT switched to REAL_NEXUS_DEVELOPMENT.
- REAL mode is exercised **on safe fixtures only** (git gates, REAL M10).
- **No PRE-DEVBRIDGE baseline restore** (that occurs only after DB-M34 final
  acceptance and an explicit human decision).

## 3. Fixture architecture

Each scenario runs on an isolated fixture under `%TEMP%\db33\<scenario>\`:

1. **Full scripts tree copied** (`scripts/` + `config/`) to the fixture root so
   `$script:DevBridgeRoot` resolves to the fixture (the preflight engine pins
   state/tasks writes to its root; there is no env override for that root).
   This keeps every real backend command reading/writing fixture state.
2. **Byte-identical copy of the canonical workbook** (`C:\Personal\Nexus.Developer\
   NEXUS_DEVELOPMENT_CONTROL.xlsx`) placed as the fixture workbook; fixture
   `config/devbridge.json` points `developmentControlWorkbook` at it.
3. **Fixture state seeds** (the harness's only direct JSON writes, all to the
   fixture):
   - `state/trial-proving-history.json` — WI-07-0.2.4 / CHG-20260830-017 /
     TRIAL_CYCLE_CLOSED / TRIAL_ONLY_UNMERGED / TRIAL entry.
   - `state/trial-closure.json` — DB-M12.4 closure record (fingerprint preserved).
   - `logs/tasks/WI-07-0.2.4/CHG-20260830-017/` — per-change overlay evidence:
     `claude-decision.json` (dbM06Result VERIFICATION_PASS, decision PASS,
     trialMode true, implementationState TRIAL_ONLY_UNMERGED, reviewedAgainstDbM06
     true), `VERIFICATION_RESULT.md`, `test-result.json` (passed/failed/total),
     `build-result.json` (warnings/errors/succeeded).
4. **Controlled external artifacts** (the human/external boundary) are written
   by the harness as fixture files: ChatGPT handoff document (generated by the
   real M05 backend), the ChatGPT output / implementation result artifact, and
   the human Claude decision (fed to the real M08 via `DB08_DECISION`).

## 8. Hardening finding (Gate 1 REAL-mode bug, fixed)

`scripts/TrialDependencyOverlay.ps1` Gate 1 previously defaulted the resolved
mode to `TRIAL` when `state/current-task.json` was absent, so on a fresh state
(e.g. a REAL-mode fixture where M03's preflight dependency analysis runs before
any current-task write) the overlay could silently let a trial-proven
predecessor satisfy a REAL-mode dependency during task selection. Fixed so the
effective mode is resolved EVERY time from config (and current-task when
present) via `Get-DevBridgeMode`, honoring `REAL_NEXUS_DEVELOPMENT` even on a
fresh state. This is the milestone's one genuine hardening change (capability
3 / `TRIAL_TO_REAL_COMPLETION_CAPABILITY NO`); scenario E proves REAL-mode
overlay rejection, scenario G's REAL task is therefore seeded post-M05 (M03's
REAL-mode block is itself proven in E).
